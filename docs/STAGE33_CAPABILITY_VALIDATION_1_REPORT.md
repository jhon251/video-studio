## 0. 实验结论（先行）

**H1：「真正让系统看见素材，能显著改善'语义相关但视觉不适合'的候选选择」——不成立。**

- R1（负例下沉率）= **0.625 < 0.80**（未达标）；
- R2（正例保留率）= 0.80（恰好达标）；
- 三档权重（0.3/0.5/0.7）结果**完全一致** → 视觉信号太弱，权重不敏感；
- 决定性证据：CLIP ViT-B-32 的 **has_person 二值检测准确率 18.8%**（低于随机 50%）——系统仍然"看不见人"，而"人物剧照/人物照片 vs 风景/图表"正是 S03/S12/S19 失败的核心区分。

## 3. 决策树判定

按既定决策树：**R1 FAIL / R2 PASS** → 视觉模型能发现部分负例，但整体区分能力不足。

但需精确表述本实验的失败模式：**不是"过度排斥好素材"（R2 恰达标），而是"负例沉不下去"**——模型无法对"人物类视觉不适合素材"形成强排斥，根因是 has_person 检测失效 + 11 类细分类不足，导致 type_fit 项对 S12/S19 类负例的惩罚打不中。

## 4. H1 为什么失败（证据链，不粉饰）

1. **CLIP 是"语义相似度"模型，不是"视觉属性检测器"**：它能算"图与文本像不像"，但 has_person 18.8% 证明它无法可靠回答"图里有没有人"——而"人物剧照/照片"正是本次失败的核心类别；
2. **候选池太小（16）且高度同质**：排序粒度太粗，62.5% vs 80% 的差距在 8 个负例上只有 1 个样本的差别；
3. **3.1.4 的语义分本身已不弱**：semantic_norm 与 visual_suitability 高度相关时，rerank 只做边际重排（Top-1 无变化）；
4. **关键负例 M-S03-162 无法下载**（Commons 429）：连"最该被识别的负例"都无法进入实验——这本身再次指向素材获取/供给的现实约束。

## 5. 局限（如实声明）

- M-S03-162（S03/S01 两个负例依赖它）下载失败，未参与排序 → 负例可评估数 8/10；即使补上，6/9≈66.7% 仍 <80%，结论方向不变；
- 正/负例标签中 4–10 为构造对照（1–3 为人工裁决），构造标签可能过松/过紧；
- 类型适配项 type_fit 是**预先固定的通用规则**（未针对负例反向调参），符合纪律要求。

## 6. 下一步建议（二选一，附证据）

**证据汇总**：视觉理解（CLIP 级）在当前素材池上无法达到 80% 负例下沉；成本虽低但能力不匹配（has_person 18.8%）；而"素材供给不足"的证据连续三轮存在（S03 无珊瑚骨架素材、关键负例下载失败、候选池仅 16）。

**建议：优先转向「素材供给」能力层，而不是继续视觉理解路线。** 理由：
1. 连续三轮失败（P1 无素材→图形卡流、V3 差素材→人物剧照+文字、CV-1 视觉理解→负例沉不下去）的**共同瓶颈是素材池的质量与规模**，不是决策层或语义理解层；
2. 视觉理解若要再做，必须换工具（人物检测器/对象检测 + 更细分类，而非 CLIP 嵌入），但那属于"检测"能力层，投入产出需重新评估；
3. 素材供给是"更多、更好的可选画面"，能同时改善三轮失败，且不依赖模型能力假设。

**最终回答 H1：不成立。** 按纪律：不进入素材理解层建设，不继续加规则/加模型堆叠。
