# V2.1 Stage 5 设计：Support Sufficiency 二级判定实验（仅设计，未实施）

> 背景基线（冻结）：4b 真实评估——Rule 68.5% → LLM 75.1%；CONTRADICTS precision 100% ✓、
> CRITICAL 双零 ✓、IRRELEVANT precision 86.3% ✗、DIRECT precision 45% ✗。
> 失败主因：LLM 把"相关"直接当"完整支持"（定义句/问句/修辞句被升 DIRECT），
> 以及 CONTEXT_ONLY/IRRELEVANT 边界漂移。
> 约束：不新增 Agent；不改 fact_check 状态机与最终结论规则；不改 50/121/26 冻结集；
> 生产接入保持禁止。

## 一、核心思想：把"相关"与"足够"拆成两层

现有 v1 LLM Judge 在**一次判断**里混合了"这条证据和 Claim 有没有关系"与
"这条证据够不够完整背书 Claim"，导致 DIRECT 判定松弛。Stage 5 拆为：

```
第 1 层：相关性分类（Relevance）
  输出：IRRELEVANT / CONTEXT_ONLY / RELEVANT + contradiction_candidate + claim_type
第 2 层：充分性清单（Sufficiency，确定性映射，不靠 LLM 感觉）
  DIRECT = 清单逐项通过；任何一项不通过 → 最多 PARTIAL
```

关键原则：**"提到了相关事实" ≠ DIRECT**。DIRECT 是清单的机械结论，不是 LLM 的一句话判断。

## 二、第 1 层：相关性分类（单次结构化 LLM 调用）

LLM 输出结构化 JSON（沿用 Router Schema 校验 + 枚举白名单）：

```
{
  "relevance": "IRRELEVANT" | "CONTEXT_ONLY" | "RELEVANT",
  "claim_type": "ASSERTION" | "QUESTION" | "DEFINITION" | "RHETORICAL" | "NARRATIVE" | "CONTRAST",
  "contradiction_candidate": true/false,      // 仅当可验证断言 + 同谓词否定时可为 true
  "subject_match": true/false,
  "object_match": true/false,
  "predicate_match": true/false,
  "qualifiers": {"第一": true, "最大": false, ...},   // 仅列出 Claim 实际出现的限定词
  "numbers_years": {"860亿": true, "2023": false, ...}, // 仅列出 Claim 实际出现的数字/年份
  "evidence_quote": "原文引用≤80字（支撑上述字段的原文）"
}
```

- **claim_type 双信号**：规则层现成的问句/第X步定义句/影视叙事句/是…还是/不是A是B 检测结果
  作为 hint 注入 prompt；LLM 可提出异议并给理由，但**裁决规则保守**：
  规则层判 QUESTION/DEFINITION/CONTRAST 时，LLM 说 ASSERTION 不生效（规则赢）。
  （4b 的 9 条"过度升 DIRECT"全部落在这些类型上，必须由确定性裁决封死。）
- **contradiction_candidate 双信号**：LLM 标记为 true **且** 规则层否定词辖域检查也命中，
  才进入 CONTRADICTS；任一信号缺失 → 不判 CONTRADICTS（precision 优先，宁可降级）。
- **CONTEXT_ONLY / IRRELEVANT 边界单独裁决**：LLM 给 relevance；规则层给出词元重叠计数。
  重叠=0 且 LLM 说 CONTEXT_ONLY → 判 IRRELEVANT（保守裁决）；重叠≥1 且 LLM 说 CONTEXT_ONLY
  → 判 CONTEXT_ONLY。两者都不参与结论计算，争议只影响审计标签不影响安全。

## 三、第 2 层：充分性清单（确定性映射表，零 LLM 判断空间）

DIRECT_SUPPORT **当且仅当**以下全部成立（任何一项不成立 → 最多 PARTIAL_SUPPORT）：

| # | 清单项 | 数据来源 |
|---|---|---|
| S1 | claim_type == ASSERTION（问句/定义句/修辞句/叙事句/对照构式一律不得 DIRECT） | 双信号裁决结果 |
| S2 | relevance == RELEVANT 且 subject_match 且 object_match（主体/对象一致，非同形异义） | LLM 结构化字段 |
| S3 | predicate_match == true（Evidence 明确陈述 Claim 的谓词：完成/实现/发布/包含/是…，不是"提到过相关事实"） | LLM 结构化字段 |
| S4 | qualifiers 全部为 true（第一/首次/首例/最大/唯一/目前/至今/基本共识/共识/已经实现/可以做到/商业化/大规模 等严格限定词逐项背书） | LLM 结构化字段 + 限定词表（数据无关常量） |
| S5 | numbers_years 全部为 true（数字/年份同值同单位；不一致即失败） | LLM 结构化字段 + 数值比较（复用中文数字解析） |
| S6 | 无 CONTRADICTS 信号 | 双信号 |
| S7 | （合并句 Claim）Evidence 覆盖 Claim 的每一个并列断言项 | LLM 字段 conjunction_covered |

- RELEVANT 但清单未全过 → **PARTIAL_SUPPORT**（宁可 PARTIAL，不得放宽任何一项换取 recall）。
- **DIRECT precision 优先于 recall**：本设计的直接后果是 DIRECT recall 将低于 4b 的 64%，
  这是预期且被接受的；报告中将单独给出 recall 下降幅度供评审。
- 清单是**数据无关常量**：限定词表来自本文件与既有规范，不从 197 样本的错误里新增条目。

## 四、CONTRADICTS：precision 优先保持不变

- 资格：claim_type==ASSERTION 且 subject/object/predicate 一致 且 双信号否定成立。
- 任何不确定（否定对象不同、构式否定、问句/定义句、语境不同）→ 降级为
  PARTIAL/CONTEXT_ONLY/IRRELEVANT，绝不为了 recall 放宽。
- 目标：CONTRADICTS precision 保持 100%；recall 允许下降（4b 漏判 CT-07 属可接受代价）。

## 五、防过拟合机制（本设计的强制纪律）

1. **三集冻结 = 只做验收，永不做开发**。Stage 5 开发只用新建 **dev 集**：
   - 第三轮 Tavily 独立检索（同 62 Claim、同查询，新 URL/新文本，~60 条）；
   - 第一轮数据库里未进入任何现有集合的存量 Evidence（约 4 条）；
   - 全部真实文本，标注流程同前（标注先行）。
2. **Prompt few-shot 只从 dev 集取**（≤6 条），禁止引用 197 样本的任何文本；PROMPT_VERSION 升级。
3. **无逐样本补丁**：决策表是全局常量，禁止任何 "if 样本号/URL" 逻辑；所有阈值在 dev 集上
   校准一次后冻结。
4. **过拟合警报**：每次 dev 调参后，在 dev 与冻结 197 上各测一次并报告两者分差；
   dev 分 - 冻结分 > 5 个百分点 → 视为过拟合，停止调参，回退上一版。
5. **验收一次性**：冻结 197 只在最终验收跑一次；结果只报告，不允许"看结果再调参"的循环。
6. **消融报告**：S1–S7 每项的边际贡献在 dev 集上单独测，任何一项贡献≈0 即从清单移除
   （防止清单膨胀成对 197 的拟合件）。

## 六、成本 / 延迟 / 缓存 / 降级（相对 v1 的变化）

- 调用次数不变（同一批边界筛选，~40/轮）；单次输出 token 从 ~60 增至 ~180（结构化字段）；
  输入 token 不变（few-shot 更少：≤6）。费用估算每轮 **$0.01–0.05**，仍在 F 档预算内。
- 延迟 p50 ≈ 1.5s 不变；缓存键新增 PROMPT_VERSION 自动失效旧缓存；两级缓存与五级降级不变。
- LLM 未配置/失败 → 回退规则层（现状），**绝不阻塞**；双信号机制在回退时退化为单信号（规则）。

## 七、验收线（不变）

DIRECT precision ≥95%；CONTRADICTS precision ≥95%；IRRELEVANT precision ≥90%；
CRITICAL（无关→DIRECT、无关→CONTRADICTS）= 0。DIRECT recall 不设下限（明示下降并报告）。
未达标 → 只报告，不调参，不接生产链。

## 八、明确不做

不新增 Agent；不改 fact_check 状态机/结论规则/阈值；不改 Claim 类型抽取；不改 reliability；
不改 fetch/provider；不改 50/121/26 冻结集；生产接入保持禁止。
