# V2.1 B 路线：Evidence Pool / Claim-level Evidence Aggregation 架构设计

> 状态：仅设计，零代码。基线：Stage 6 冻结验收（Rule 68.5% / 4b 75.1% / S5 74.1% / S6 78.2%；
> DIRECT precision 47.8% ✗、IRRELEVANT 84.5% ✗、CRITICAL=3 ✗、CONTRADICTS recall 100% ✓）。
> 本设计只回答架构/数据流/判据/实验方案；阈值均为候选方案，不在本阶段定死。

## 一、为什么单条 Evidence 粒度失败（基于三轮实验的硬证据）

1. **DIRECT precision 三版从未超过 78.6%**（4b 45% → S5 78.6% → S6 47.8%），且 S5/S6 两版都出现
   "无关 Evidence → DIRECT" 的 CRITICAL 错误。原因不是清单不够细，而是**单条 Evidence 的局部信号
   天生含噪**：S2/S3（主体/对象/谓词）只能依赖 LLM 单点布尔，弱相关页面（卖货页、刑法文、游戏帖）
   被 LLM 判 true 后，没有任何跨证据机制能把它过滤掉——确定性清单只守数字/限定词，守不住"命题层面"。
2. **CONTRADICTS 在单条粒度上其实已经可用**（S6：recall 100%、precision 92.3%），说明"信号提取"
   与"最终裁决"必须分层：单条 Judge 适合产信号，不适合产最终状态。
3. **互补与冲突在单条粒度上不可表达**：一条证据只证明数字、另一条只证明限定词——单条判定时两者
   都只能 PARTIAL，但组合起来可能足够；同样，"2 SUPPORT vs 1 CONTRADICT"的裁决需要来源独立性、
   可靠性、特异性、时间相关性，这些信息单条 Judge 根本看不到。
4. 结论：**抽象层级错了**。需要把判断单元从 (Claim × Evidence) 提升为
   (Claim × Evidence Pool → Claim 状态)。

## 二、抽象层级改变

```
旧（单条）：Claim + Evidence → [LLM/规则] → DIRECT/PARTIAL/IRRELEVANT/CONTRADICTS（最终）
新（B）：   Claim → Evidence Pool → 每条 Evidence 的多维信号
                → 确定性 Claim-level 聚合（coverage/独立性/可靠性/冲突）→ support state
```

- 单条 Judge 降级为**信号提取器**：输出多维布尔信号与来源元数据，**不再输出最终支持等级**。
- 最终 support state 在 Claim 层由确定性聚合产生，可审计、可解释。
- 下游 fact_check 的结论综合/人工闸门/状态机**完全不动**（聚合层产出的 support state 映射为
  现有 support_level 输入；集成另阶段验收，本设计不接生产链）。

## 三、Evidence Pool 的形成

### 3.1 入池
- 检索（Tavily 主 + 免密钥回退）→ 预筛（URL/黑名单/关键词重叠，保留现状）→ fetch →
  提取窗口（现状）。fetch 失败候选不入池，但计入池统计（fetch_failed）。
- 每 Claim 池容量上限：**候选 12 条、去重聚类后有效 Evidence ≤ 8 条**（设计参数，可调）。

### 3.2 去重与"复制链"识别
- 三级去重（全部确定性，零新依赖）：
  1) **URL 精确去重**；
  2) **内容指纹聚类**：归一化（去空白/标点/繁简）后的正文 8-gram 集合 Jaccard ≥ 0.8，
     或标题+首段指纹相同 → 同一证据簇；
  3) **转载链识别**：不同 domain 但内容指纹同簇 → 标记 syndicated=true。
- **"10 个网页复制同一内容" = 1 个证据簇**：簇内 count 记 dup_count，独立性权重恒为 1；
  簇对外只贡献一份信号（取簇内抓取质量最好的一份正文作为代表）。

### 3.3 来源/domain 聚类与分层
- 按 domain 聚簇（同 domain 多 URL 先按 3.2 去重；同 domain 不同内容算同源，独立性受限）。
- 来源分层（复用 V2.1 阶段 4 设计的 reliability 分层方向，作为池元数据）：
  **一手**=政府/监管文件、法院判决、官方公告、学术论文/预印本、专利；
  **二手**=主流媒体、专业媒体、科学新闻；
  **百科**=百科/词典；
  **商业**=电商/定价/营销/公司 PR；
  **论坛/社交**=论坛、贴吧、社媒帖；
  **未知**。
- 分层规则 = domain 规则 + 内容标记（数据无关通用规范），**分层只作权重输入，不决定结论**。

### 3.4 独立性
- 有效独立源数 = 去重聚类后的簇数（跨 domain 才计 full 权重；同 domain 不同簇计 0.5）。
- source diversity 要求：DIRECT 候选至少涉及 ≥2 个独立来源类（如一手+二手，或两枚不同机构一手）；
  单一来源（即使内容完全匹配）只能到"单源候选"路径（见 §6）。
- **independent source diversity**：不同机构/不同 domain 才算独立；转载/聚合站/同一集团多站点不计。

## 四、单条 Evidence Judge 的定位（降级为信号提取器）

输出 schema（EvidenceSignal，每 Evidence 一条）：

```
evidence_id, claim_id, source {url, domain, source_class, reliability, pub_date, fetch_status},
topic_relevance: bool,            # 讨论同一主题域（必要但不充分）
proposition_relevance: bool,      # 针对该命题的谓词/对象/限定词层面相关（支撑/反驳的必要条件）
claim_type_compat: ASSERTION|QUESTION|DEFINITION|RHETORICAL|NARRATIVE|CONTRAST,
subject_match, predicate_match, object_match: bool,
qualifier_match: {限定词原文: bool},      # 键集由规则层注入（S6 机制保留）
numeric_match:    {数字/年份原文: bool},  # 键集注入 + 原文确定性复核（S6 机制保留）
contradiction_candidate: bool,
contradiction_scope: {element: subject|predicate|object|qualifier|number} | null,
evidence_quote: str
```

- ① **topic vs proposition 分开**（Stage 6 问题 A 的正面回答）：topic_relevance 只判"同域"；
  proposition_relevance 判"是否针对该命题的谓词/对象/限定词"。**只有 proposition_relevance=true
  的证据才能贡献支撑或反驳**；topic-only 证据只进池统计，永不参与 support 计算。
- ② contradiction_candidate 沿用 Stage 6 独立语义（recall 100% 已验证），规则辖域仅审计。
- ③ claim_type_compat 沿用 Stage 6 规则裁决（问句/第X步/对照构式等不可反驳、不可 DIRECT）。
- 最终五类标签**不再由 Judge 产出**；Judge 产出的信号汇总到 Claim 层聚合。
- 本层验收：沿用冻结 197 做"信号级"验收（s2/s3 对 IRRELEVANT 页的假阳率、
  contradiction recall/precision、qualifier/numeric 提取准确率）——197 仍是信号层冻结验收集，
  不是聚合层验收集。

## 五、Claim-level 聚合层（确定性）

### 5.1 Claim 要素分解
- 规则层把 Claim 分解为要素集 E = {subject, predicate, object, qualifiers..., numbers/years...}
  （键集注入机制复用）。

### 5.2 Evidence Coverage Matrix
```
要素 \ Evidence   E1(一手,官方)  E2(二手,媒体A)  E3(二手,媒体B)  E4(论坛,转载E2)
subject               ✓              ✓              ✓             ✓
predicate             ✓              ✓              ✓             ✓
object                ✓              ✓              ✓             ✓
qualifier:最大        ✓              ✓              –             ✓(复制)
number:2025           ✓              ✓              ✓             ✓(复制)
```
- 行列均为确定性信号（Judge 信号 + 原文复核）。
- 聚合推导：element_covered[e] = 任一 proposition_relevant 证据覆盖 e；
  覆盖源计数按**独立簇**计（E4 与 E2 同簇 → 不增加计数）。

### 5.3 冲突矩阵（与反驳分离）
- **证据之间互相矛盾**（E1 说 2025、E3 说 2024）≠ **证据反驳 Claim**：
  前者进冲突检测（复用现有 conflict_detector 路线，必审）；
  后者由 contradiction_candidate 进反驳子系统（§7）。
- 元素级冲突：同一要素在不同独立证据间取值不一致 → element_conflict[e]，聚合时该要素降权并
  标记人工复核；**裁决不按 2>1 多数票**，按 §5.4 权重。

### 5.4 冲突/支撑权重（候选，不设死阈值）
```
权重(e) = reliability_class(e) × independence(e) × specificity(e) × temporal_relevance(e)
independence: 去重簇内=1/簇；同 domain=0.5；跨域独立=1
specificity: proposition_relevance 且覆盖元素数/Claim 要素总数
temporal_relevance: 证据时间与 Claim 时间限定词的贴合度（时间冲突 → 0 并标记）
一手来源对二手来源：不设"一手必胜"规则，但一手+矛盾时优先一手并保留冲突审计
```
- 未解决的冲突 → 冲突路径（人工），绝不静默选边。

## 六、DIRECT 判据（候选方案，按情形分列；阈值待 dev 集校准）

核心定义改造：**DIRECT ≠ 某条证据足够相关**，而 = 
"存在一个**独立、可靠、且与 Claim 完全匹配的证据集合**（集合可含 1 条）"。

| 情形 | DIRECT 候选条件（设计意向） |
|---|---|
| 单一一手来源 | 一手来源单条覆盖 S+P+O+全部限定词+全部数字 → **DIRECT**（权威性可替代冗余；如官方公告/判决/论文原文） |
| 两个独立来源 | ≥2 独立簇、每簇 proposition_relevant、并集覆盖全部要素、无元素冲突 → **DIRECT** |
| 多个二手来源 | 仅二手：≥2 独立媒体簇 + 全要素覆盖 + 互相一致 → DIRECT 候选（保守方向：默认 Mostly，加一手源升级） |
| 来源互相复制 | 复制链归并为 1 簇 → 按"单一来源"处理，二手复制链最多 **Mostly** |
| 数字事实 | 数字要素须被 ≥1 可靠性≥媒体级来源精确覆盖；池内任何独立源数字冲突 → 该要素冲突路径，不 DIRECT |
| 历史事实 | 优先一手/权威史源；百科单独仅作辅助（不单独支撑 DIRECT） |
| 科学事实 | 需学术/官方源覆盖核心断言；媒体转述可作冗余但不可作锚点 |
| 预测/观点 | **永不 DIRECT**（类型门槛，沿用现状人工路径） |
| 锚点要求 | DIRECT 集合中必须存在 ≥1 条"锚点"证据：单条覆盖 S+P+O 且 proposition_relevance=true 且可靠性≥媒体级；其余要素可由互补证据补足 |
| 兜底 | 任何 CRITICAL 限定词（第一/最大/唯一/首次/目前）缺任一独立源覆盖 → 不 DIRECT |

## 七、CONTRADICTS 独立子系统（保留 Stage 6 成果）

- 识别层：Stage 6 独立语义信号（recall 100%），**不回塞 SUFFICIENCY 清单**。
- Claim 层判 Disputed 前逐项审查（deterministic）：
  1) 是否针对同一 Claim（claim_id + 要素对齐）；
  2) 否定落在哪个要素（subject/predicate/object/qualifier/number）；
  3) 是否只是时间不同（时间要素冲突 → 走元素冲突路径，不判反驳）；
  4) 是否只是限定词不同（→ 限定词冲突路径）；
  5) 是否"不是A而是B"构式（→ 非反驳）；
  6) 是否来源级互相矛盾（→ conflict_detector 路线，非反驳）；
  7) 是否只是上下文不同（→ CONTEXT_ONLY 信号）。
- 任一 contradiction_candidate 通过审查 → Claim 级 CONTRADICTS（沿用 Disputed+人工，永不 False）。
- "证据互相矛盾"与"证据反驳 Claim"是两条独立流水线，分别落 conflict 表与 support state。

## 八、CONTEXT_ONLY / IRRELEVANT 判据（池级）

- 池内全部证据 topic_relevance=false 且词面重叠=0 → 沿用现有"无相关结果"路径。
- 存在 topic-only（词面级）证据但无 proposition_relevant 证据 → Claim 级 CONTEXT 状态
  （对应现有 CONTEXT_ONLY/NO_RELEVANT 的路径区分，保留 5 类 verification_path 不变）。
- 注意：这两个状态的单条边界模糊问题在池级自然消解——**不逐条判边界，只看池内是否出现
  任何 proposition_relevant 证据**。

## 九、三种聚合架构比较（不预设 C）

| 维度 | A 规则聚合 | B LLM 聚合（池级一次调用） | C 混合（信号 LLM + 确定性聚合） |
|---|---|---|---|
| 安全性 | 高（可证明） | 低（prompt 不可验证；S6 已现 few-shot 漂移） | 高（安全门是代码） |
| 可解释性 | 高 | 低 | 高（coverage/冲突矩阵可审计） |
| 泛化能力 | 信号质量受规则上限约束（历史盲测 65%） | 语义最强但最易过拟合 | 信号层已验证（contradiction 100% recall）；聚合规则少且全局 |
| 成本 | ≈0 | 1 次调用/Claim | N 次调用/Claim（N=池大小≤8） |
| 延迟 | ≈0 | ~1.5s/Claim | ~4-6s/Claim（并发） |
| 抗垃圾证据 | 差（规则信号本身最弱） | 中（一次判断含池，但无可审计安全门） | 好（独立性+可靠性+锚点三重过滤） |
| 多源互补 | 可实现（矩阵是规则） | 靠 LLM 判断 | 矩阵确定性推导，直接支持 |
| 冲突处理 | 可规则化 | 靠 LLM，风险高 | 确定性权重+人工兜底 |
| 过拟合面 | 规则阈值（少量） | prompt（大） | 信号 prompt（已被 197 验收约束）+ 少量全局阈值 |

**推荐：C（混合）**，理由：把"已验证可靠的部分"（S6 的信号提取：contradiction、qualifier/numeric、
claim_type）留在 LLM 层，把"需要安全证明的部分"（coverage/独立性/冲突/锚点）放在确定性层；
A 作为 LLM 不可用时的降级路径；B 仅作研究对照（一次性实验，不作生产候选）。
**诚实的结构性风险（不回避）**：C 仍依赖 s2/s3 信号质量——S6 中 LLM 对弱页 s2/s3 假阳是 DIRECT
塌缩的直接原因。因此 C 的前置条件：信号层必须先通过"topic/proposition 分离 + s2/s3 对
IRRELEVANT 页假阳率"专项验收（用冻结 197 测信号，不测聚合）；若 s2/s3 假阳率不达标，
则 B 路线整体不值得按 C 实施（见 §12）。

## 十、失败降级与审计

- 池为空/fetch 全失败 → 现有 5 类 verification_path 原样保留（SEARCH_FAILED/FETCH_FAILED/
  NO_RELEVANT_RESULT/NO_RELIABLE_SOURCE/INSUFFICIENT_EVIDENCE）。
- LLM 不可用 → 信号层退化为规则信号，聚合层照常运行（A 路径）。
- 聚合层异常 → 回退单条 Judge 现状行为（降级不阻塞）。
- 审计：新增 claim_support_state 表（claim_id、要素覆盖矩阵 JSON、独立簇清单、锚点 evidence_id、
  冲突元素清单、support_state、判据版本、时间戳）；每条 EvidenceSignal 存信号表；
  决策可完整回放。

## 十一、成本/延迟估算

- 每 Claim：池 ≤8 条 → 8 次信号调用 × ~$0.0004 ≈ **$0.0032/Claim**；
  50 Claim/轮 ≈ **$0.16/轮**（与 4b/5/6 同量级）；缓存/降级沿用。
- 延迟：4 并发 ≈ 池收集后 **+4-6s/Claim**（相对单条判定）；可接受（离线核查场景）。

## 十二、实验方案与验收设计（暂不跑冻结 197）

1. **信号层专项**（用冻结 197，只测信号不测聚合）：topic/proposition 分离后的 s2/s3 假阳率、
   contradiction recall/precision、qualifier/numeric 提取准确率。达标线：s2/s3 对 IRRELEVANT 页
   假阳率足够低（具体值待 dev 校准，方向：≤ 4b 历史水平的一半）。
2. **聚合 dev 集**（新建，label-first）：用现有真实采集池按 Claim 聚合（R1 入库 + 盲测 + dev
   三轮采集按 claim 归组，全部真实文本），人工标注 Claim 级 support state；与冻结 197 无元素重叠；
   不用于 prompt 调参（few-shot 仍只取聚合 dev 内标注先行样本）。
3. **聚合验收线（候选）**：DIRECT precision ≥95%（Claim 级）、CONTRADICTS precision ≥95%、
   无关池→DIRECT=0、无关池→CONTRADICTS=0；PARTIAL/IRRELEVANT 边界仍单独报告。
4. 消融：coverage 并集 / 独立性归并 / 锚点要求 / 冲突权重 四项开关对聚合 dev 的边际影响。
5. 冻结 197 的角色：**仅作为信号层验收集**；聚合层验收用新建聚合集。绝不据聚合结果回头改信号 prompt。

## 十三、最终结论

**B 路线值得实现，但必须按 C（混合）实现，且以"信号层 s2/s3 假阳率达标"为硬前置。**
单条粒度的失败是结构性的（三次实验 DIRECT 未破 78.6%、CRITICAL 反复出现），聚合层直接攻击
该失败模式；同时 B 路线不推倒已验证的资产（Stage 6 的反驳子系统、S4/S5 确定性复核、
繁简归一、双轨审计全部保留为信号层组件）。若信号层前置验收失败，则说明瓶颈仍在语义提取本身，
届时 C 与 B 路线整体都应放弃，退回"人工优先 + 聚合信号只做提示"的最小方案。
