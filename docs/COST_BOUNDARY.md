# 成本边界与对账口径（3.x Final / Phase 3-C）

> **一句话**：本系统**没有任何真实账单接口**。所有金额都是 `token × 官方价目表` 的**估算**；
> 外部素材（Wikimedia Commons）**免费**，只记**用量**；Phase 1.1 的 **¥3.24 残余**的正式结论是
> **估算差额、客户端不可归因（NOT_ATTRIBUTABLE_CLIENT_SIDE）**，不是台账算错，也不是账单。
>
> 证据：`docs/regression_2x/logs/phase3c_cost_boundary.json`（可随时重跑：
> `python docs/regression_2x/phase3c_cost_boundary.py`）

---

## 1. 三条口径必须分开看（禁止混算）

| 口径 | 内容 | 性质 | 是否可复核 |
|---|---|---|---|
| **A. LLM 成本** | `tasks.cost_usd` 合计 + `LLM_CALL` 事件的 token/金额 | **估算**（token×价目表）；客户端无账单接口 | ✅ 可（同库重算，见 §2） |
| **B. 外部素材用量** | provider 请求数/下载字节/限流次数/重试；本地缓存文件与字节 | **用量**，**不是金额**（Wikimedia 免费、无 key、无付费额度） | ✅ 可（重读产物 + 磁盘） |
| **C. 账户余额** | DeepSeek `/user/balance`（免费只读接口） | **服务端真值**，但**异步/批量结算**且可能含其它调用方用量 | ⚠️ 可读，但**不可逐笔归因到本项目** |

**禁止**：把 A 写成"账单"；把 C 的余额差当成 A 的验证；用 C 倒推单价；为了凑平而修改本地数字。

## 3. ¥3.24 残余：正式结论

### 3.1 事实（Phase 1.1 实测，`PHASE1_1_REPORT.md` §1.3）

| 口径 | 金额 |
|---|---|
| 余额：15.95 → 11.17 CNY | **-4.78 CNY** |
| 本地台账 A/B/C（49 次 / 218,349 tokens） | ≈¥1.08（$0.1517 @7.1） |
| 诊断性调用（3 探针 + 2 受控测量） | ≈¥0.46 |
| **无法归因残余** | **≈¥3.24** |

### 3.2 机制复验（本次重跑，可复现）

`phase3c_cost_boundary.py` 在**本地零 LLM 调用**窗口内轮询余额：

| t(s) | balance (CNY) | 本地 LLM 调用 |
|---|---|---|
| 0 | 8.79 | 0 |
| 20.4 | 8.79 | 0 |
| 41.3 | 8.53 | 0 |
| 61.5 | 8.53 | 0 |

窗口内 `local_llm_calls_in_window = 0`、`local_events_added_in_window = 0`，余额仍下降 **-0.26 CNY**。
→ 直接复现了"**余额变化不能归因于本地调用**"这一机制（异步/批量结算，或同一 key 的其它调用方）。

### 3.3 正式结论

- **分类**：`NOT_ATTRIBUTABLE_CLIENT_SIDE`（估算差额；**既不是账单，也不是台账错误**）。
- **数量口径**：≈¥3.24，**估算值**（人民币数值依赖 7.1 的换算率，该换算率客户端不可验证）。
- **候选原因**（客户端无法进一步区分，故不强行归因）：
  1. 同一 API key 被其它调用方使用；
  2. 更早窗口的费用仍在异步/批量结算（已直接观测到延迟到账）；
  3. 客户端不可观测的计价细节（USD/CNY 换算率、服务端舍入/阶梯）。
- **纪律**：Phase 1.1 起即**没有修改任何数字去凑平两边**；本阶段同样不做，只把口径与证据固化。

## 4. 日常使用建议

- 想知道"这个项目花了多少" → `run.py report <project_id>` 看 **成本（LLM，估算）** 小节（口径 A）；
- 想知道"用了多少外部素材" → 同报告的 **外部素材用量（非计费）** 小节（口径 B）；
- 想核对账户真值 → `python docs/regression_2x/balance_trajectory.py`（口径 C，只读、免费），
  但**不要**用余额差做逐项目对账；
- 预算保护 → `llm.max_total_usd`（默认 0.60）：超预算在**发请求前**抛 `LLM_BUDGET_EXCEEDED`。
