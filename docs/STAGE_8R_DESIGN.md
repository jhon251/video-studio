# Stage 8R：Final Boundary / RC Adjudication Design

> 状态：**设计待裁决**。只设计、不执行；不修改生产代码与冻结产物；不进入 3.x；不允许为过验收改阈值。
> 本轮目标：判断 8Q 两个 NO-GO 是否为 2.x 真正 blocker，还是应正式登记为 3.x 边界；并给出 2.x Definition of Done 与 RC 裁决规则。

## R1：专业媒体成本模型边界诊断

### 1. 三套成本标准的定义差异

| 标准 | 生产方式 | 成本结构 |
|---|---|---|
| 个人创作者 | 单兵串行：脚本→录音→剪辑→图表→审校全自己做，无资产复用，返工自理 | 内容成本 = 全量单人工时；生命周期开销大（无分工） |
| 小团队（2-3 人） | 分工并行：出镜/剪辑/动画分人，少量模板复用，含协作成本 | 内容成本略降 + 协调开销 |
| 专业媒体（流水线） | 编导/摄影/后期/审片并行，模板库 + 资产库，高产速 | **内容成本本身被压缩**（专家 + 模板），另有审核层 |

### 2. lifecycle overhead 为何无法解释专业媒体效率

8Q 模型：`calibrated = content_min/60 × (1 + lifecycle_overhead)`。lifecycle 是**内容之后**的乘数，只能"加"不能"减"内容成本。专业媒体的效率发生在**内容侧**（专家+模板把单个场景做快），模型没有内容侧缩放项 → 求解 `(1+overhead) = 专业带中位 / content_min` 得到 **−0.21（负 overhead，无意义）**。

### 3. efficiency factor 是新成本模型，不是校准

引入 `cost = base × complexity × efficiency_factor(标准)` 是**新增参数维度**（内容侧缩放），超出"校准 lifecycle 系数"范畴，属**模型扩展**，不是参数微调。

### 4. 仅用于诊断的 sensitivity 分析（VIDEO-10：content=1005.1min=16.75h，专业带 [10,15]h，带中位 12.5h）

| 假设 lifecycle overhead | 需要的 efficiency factor（诊断值） |
|---|---|
| 0.0 | 12.5 / 16.75 ≈ **0.746** |
| 0.1 | 12.5 / (16.75×1.1) ≈ **0.678** |
| 0.2 | ≈ **0.622** |
| 0.25 | ≈ **0.597** |

诊断结论：专业流水线把场景内容做快至个人费率的 **60-75%**——与"专家+模板+并行"的现实直觉吻合，但必须新增 efficiency factor 维度才能表达。

### 5. 是否影响 2.x 核心目标

**不影响**。2.x 核心目标 = 个人创作者/小团队完成 10-15 分钟科普/事实类视频（8Q 两标准均已校准入带 PASS）。专业媒体标准是 8O 引入的**对照基准**，不是交付目标；本系统无 Agent、无素材库、无生产接线，专业流水线在本系统边界之外。

### 6. 裁决

- **非 2.x blocker**。
- 登记为 **3.x Enhancement**：「专业媒体效率因子 + 资产/并行工作流建模」。
- 禁止为 PASS 修改现有阈值（lifecycle 1.05/0.26 冻结不变）、禁止制造负 overhead、禁止给 专业 单独放宽现实带。

## R2：SC-TL 极端密度边界诊断

### 三档构造（数据来自 8Q 回放 `r1_stage8q_full.json`）

| 档 | 样本 | avg 密度 | 自适应带 | 判定 |
|---|---|---|---|---|
| 普通 claim | existing-1..5（真实 49 条抽样） | 1.0-3.0 | [0.5,4.0] | PASS |
| 高事实密度 | SC-HD（8 数字）/ SC-ALL（7 数字） | 5.222 / 5.375 | [2.0,8.0] | PASS |
| 极端时间线 | SC-TL（6 年份 + 11 实体） | **8.6** | [2.0,8.0] | FAIL（唯一） |

### 1. 8.6 是否只出现在极端 stress case

**是**。49 条真实 claim + 4 条其它 stress claim 全部在带内（8Q 11/12，唯一失分即 SC-TL）。SC-TL 是 8M 专门构造的极端压力样本，真实检索 claim 中无同类。

### 2. 普通及高密度 claim 是否已达标

**是**。普通 [0.5,4]、高密度 [2,8] 两档全部 PASS（见上表）。

### 3. 密度口径的深层诊断（关键发现）

逐 scene 检查 SC-TL（数据）：

- S01 hook 1 项、S02 body **17 项**、S03 fact 6 项、S04 fact 6 项、S05 conclusion 13 项，合计 43 次。
- **43 次 emphasis 仅来自 17 个不同元素**（6 年份 + 11 实体）；同一年份在 4-5 个 scene 重复出现。
- SC-TL fact 场景含 **23 条事实引用**（6 个数字 × 多个证据源，如"2013→[1]、2013→[2]、2013→[5]"），8Q fact 拆分把 23 条拆两半后，**每个半片仍含全部 6 个年份** → 重复计数加倍。

**结论：8.6 是度量伪影（同元素跨 scene 与多源引用的重复计数），不是真实制作过载**。该计划的 5 个 scene（hook/论证/两条核查/结论）对时间线 claim 是合理制作量。

### 4. entity weighting 是否 2.x 必需修复

**不是**。实体/数字/事实项分权、以及"去重计数（unique element / scene）"属于**细粒度内容适配**：2.x 的密度带 + fact 拆分已覆盖全部真实与高密度场景；仅构造型极端样本 + 度量重复伪影落败。判定为 **3.x Enhancement**。

### 5. 禁止改阈值

8.0→9.0 等"为过验收放宽阈值"**明令禁止**；正确方向是 3.x 的度量细化（分权/去重），而不是 2.x 调数。

### 裁决

- **非 2.x blocker**。
- 登记为 **3.x Enhancement**：「密度细粒度加权（实体/数字/事实项分权 + 跨 scene 重复去重）」。

## R3：2.x Definition of Done

### MUST HAVE FOR 2.x（核心能力，缺一不可）

| 域 | 能力 | 证据 |
|---|---|---|
| Truth/Evidence | B 路线四结构（Evidence Pool→Signal→Aggregation）+ 冻结 SHA256 | 8A-8B.1、8C-8D、全阶段回归 |
| Evidence 可用性 | 编码/正文修复 + 检索回退 + source_quality | 8D、8E（可回放） |
| Evidence Readiness | completeness/source_quality/balance/readiness 决策准备 | 8F |
| Research Brief | Claim Structuring 拆解 + Evidence 映射 + 缺口 | 8G（gold 20/20） |
| 创作链 | Content Plan → Script Blueprint → Draft Script，引用保持 100% | 8H、8I、8J |
| Creator Style | 频道风格化，证据保持 100% | 8K |
| Visual Planning | Script→Scene + Scene Budget(≤8) + Visual Diversity(≤3) + 时长目标 | 8L、8N（VIDEO-10/15 达标） |
| Cost Calibration | cost_base ∈ 带 100% + 个人/小团队 calibrated ∈ 现实带 | 8P、8Q |
| 信息-视觉平衡 | 数据表达覆盖 ≥60%（扩展口径）+ 密度带自适应 + fact 拆分 | 8Q（12/12） |
| 素材可获得性 | difficulty 分类 + fallback + 困难 ≤15% 硬约束 + 证据零漂移 | 8P、8Q（12/12） |
| 回归/冻结 | 15 套件 0 失败 + SHA256 不变 + 无生产接线 | 每阶段末校验 |

### ACCEPTABLE 2.x BOUNDARY（文档化接受）

1. **专业媒体成本标准**：作为对照基准报告（当前超带 12%），不作 2.x 交付目标。
2. **中+困难素材 ≤45% 软预算**：数据可视化天然属"中"素材，接受并文档化。
3. **数据表达覆盖采用扩展口径**（fact 卡计入视觉数字表达）。

### 3.x ENHANCEMENT（登记，不阻断 2.x）

1. 专业媒体效率因子 + 资产/并行工作流建模（R1）。
2. 密度细粒度加权 + 跨 scene 重复去重（R2）。
3. 素材库/许可素材接入。
4. 平台级细粒度节奏/密度适配。
5. 昂贵变体（概念动画）成本优化。
6. 多 Agent 并行制作。
7. 极端内容（多时间线超密）专项适配。

**回答两个特别问题**：2.x **不需要**支持专业媒体生产效率（目标用户是个人/小团队）；2.x **不需要**覆盖极端高密度内容（自适应带已覆盖普通与高密度档）。

## R4：最终 RC 裁决规则设计

### GO 条件（全部满足）

1. §R3 全部 **MUST HAVE FOR 2.x** 满足（以 8L→8Q 证据链逐项核验）。
2. 8Q 两个 NO-GO 均被证明为**非核心边界**：R1 专业媒体 = 3.x efficiency factor；R2 SC-TL = 构造型极端样本 + 度量重复伪影。
3. **未通过修改验收阈值制造 PASS**：lifecycle 1.05/0.26 冻结、密度带 8.0 上限不变、无负 overhead、无单独放宽。
4. Truth/Evidence 冻结边界未变（SHA256 + 冻结测试）。

### NO-GO 条件（任一即否）

1. 任一 2.x MUST HAVE 未满足。
2. 普通 10-15 分钟个人/小团队场景存在系统性失败（时长、引用、视觉重复、密度带等真实 claim 级失败）。
3. 出现以放宽阈值/制造负值方式"过验收"的行为。

### 特别约束

- **不新增 Stage**：若 R1/R2 证据足以证明两问题属 3.x 边界，直接建议 **2.x RC = GO** 并停止扩张 2.x。
- 本轮仅设计；裁决执行时按 R4 输出最终 GO/NO-GO。
