## 二、Q1：HARD_NEGATIVE ≥10 是否仍应作为硬门槛？

**回答：不应作为"硬门槛"（Gate），但应作为"最低样本量要求"的组成部分。**

理由：
1. **HN 是测试集构成，不是被测系统的性能指标。** Gate 应衡量"检索/过滤是否把可用素材排前、把不可用素材排后"，HN 数量衡量的是"测试集是否覆盖了最难区分的一类"。两者性质不同：HN 数量不足属于"证据不足（INCONCLUSIVE）"类问题，不是"系统失败"；
2. 但**HN 若为 0，则"negative sink / 硬负例下沉率"这一核心指标完全失去意义**（分母为 0），A/B/C 区分度坍缩。所以"≥某个正数"仍是**必要的测试集完整性要求**，只是它约束的是**实验能否得出有效结论**，而不是"实验是否 PASS"；
3. 预注册的 `meets_minimums` 已正确地把 HN≥10 作为"冻结前置条件"而非"结果达标"（`run_abc.py` 里 `meets_minimums` 只是审查项，不影响指标计算）——但当前 `meta.meets_minimums=false` 导致不能冻结、不能运行，这个链路本身是对的。

**建议**：把门槛拆成两块——
- **测试集完整性门槛**（冻结前置）：SP≥20 且 SN≥20 且 **HN≥10**（或经人工确认的替代口径，见 Q7）；
- **实验结果门槛**（Gate 判定）：沿用 §5.1 预注册成功线（B 达标 / B 不+C 达标 / B/C 均不达标 / INCONCLUSIVE），**与 HN 数量无关**。

## 三、Q2：当前 3 个 HN（严格 0 个）是否足以做有意义的供给实验？缺的到底是什么？

**回答：不足。** 缺的不是"数量"，而是"**一组能区分检索相关性与视觉适合性的困难样本**"。

具体缺的：
1. **严格定义下的 HN = 0**：既没有样本能验证"C 组视觉过滤到底能不能把'语义相关但视觉错位'的素材压下去"，也没有样本能验证"语义检索会不会把剧照/油画/示意图当强正例推上来"——这恰是本阶段要回答的核心问题（A→B 与 B→C）；
2. **3 个历史失败案例都没落进 HN**：S03（剧照）B=LOW、S19（沙滩孩子）B=MEDIUM、S12（油画）A=USABLE——人工裁决如此，尊重。但这意味着**"高级语义陷阱"在现有 59 个自然候选里是 0 发生**；
3. **原因清楚**：现有 59 个候选来自"锚定查询的 Top-20 召回 + 白名单"，而 Commons 的 Top-20 检索结果天然偏向"照片/图表"——**自然检索几乎不会把剧照、油画、扫描 PDF、漫画推送到前列**。这不是"素材不存在"，是"检索召回口径里缺这类样本"。HN 缺位说明的是**检索层与过滤层的可测性问题**，而不是素材世界的供给问题。

**结论：要回答 A→B / B→C，必须先有 HN；要得到 HN，靠自然召回拿不到——这就是 Q3 的前提。**

## 四、Q3：定向构造高语义陷阱候选（C）是否方法论合理？严格说明原因。

**回答：合理，且是当前唯一在实验上站得住的选择。理由如下：**

1. **HN 的存在性证明**：HN 的客观定义是"语义相关 + 视觉不适合"的**素材**。这类素材在 Commons 上**存在且可验证**（剧照/油画/扫描件/漫画/示意图都是真实文件）。定向检索只是"按语义去取真实存在的文件"，不是合成样本、不是伪造标签；
2. **构造独立于被测系统**：选取规则=镜头语义主体 × 已知失败类型（如"S12 渔民拉网 × 油画"），**不读取被测系统（检索器/过滤器的输出、分数、排名）**。这是构造式测试集的标准做法（adversarial sampling / hard example mining），只要"构造规则先于系统输出确定"，就不会因系统表现而偏置；
3. **人工标签仍然是唯一标签来源**：构造集只决定"哪些素材进入测试集"，`visual_usability / semantic_relevance / label_role` 仍由人工冻结。**没有任何一环用模型生成标签**——这与其他方案的关键区别；
4. **与"机械随机抽样"的关系**：机械随机抽样**已经证明**（59 个样本 HN=0）自然密度不足，继续抽样只是把 0 稀释成"更小的无穷小"，且**不可控**——无法保证覆盖已知失败类型（剧照/油画/扫描/漫画各需要若干）。定向构造则是**按预注册类型清单逐一填充**，可以保证每类 ≥1；
5. **与"修改已有标签/降门槛"（B）的区别**：B 是**数据操纵**（把 B=MEDIUM/LOW 的样本改成 HIGH，或把门槛降到 3），制造出的"达标"是假的，直接污染实验。**REJECT。** 定向构造不动任何已有标签、不降任何门槛，只是**新增测试样本**；
6. **唯一风险点与对策**：构造集全部是"语义相关"候选，可能导致 HN 比例过高（distribution shift）→ **对策**：构造集作为**独立子集**（一个专门回归集），指标分别报告"自然集"与"构造集"，Harness 允许标注 `subset` 维度；同时在报告中明确"构造集的存在不改变自然集的测量，主判定以自然集+构造集合并为准或分列"。这是预注册声明，不事后追认。

**结论：C 是方法论上合理且必要的；A 已实证无效；B 是污染，REJECT；D 是早退，见 Q8。**

## 五、Q4：HN 专项补充集设计（≥10 新增候选）

见同目录 `hn_pool_design.json`（探测输出）与 §六。设计规格：

| 项 | 规格 |
|---|---|
| 规模 | ≥10 个新增候选（目标 12–14，覆盖 §六 9 类，每类 ≥1） |
| 来源 | 仅 Wikimedia Commons，真实可获取文件（API 实测存在 + 许可合规 + 有缩略图） |
| 构造规则 | 定向：镜头语义主体 × 已知失败类型（预注册清单，先于任何系统输出） |
| 标签 | **全部留空**，`visual_usability / semantic_relevance / label_role` = null，等人工冻结 |

**人工标注协议不变**：三字段，A/B/C，人工直接回答；label_role 若与严格定义冲突，以人工为准并披露，但**构造集的目标就是严格 HN**——人工核对 A=NOT_USABLE 且 B=HIGH 后可直接确认，不确认就标成别的（尊重人工）。

## 七、Q6：不得以 NOT_USABLE/LOW 冒充 HN（重申严格定义）

**完全同意，且必须收严：**
- 严格定义：`semantic_relevance=HIGH` **且** `visual_usability=NOT_USABLE`，两者缺一不可；
- `NOT_USABLE + LOW` = 普通强负例（STRONG_NEGATIVE），不是 HN；
- `NOT_USABLE + MEDIUM` = 弱负例，不是 HN；
- `CONDITIONALLY_USABLE + anything` = 中间态，不是 HN（也非 SN）；
- **当前 3 个 label_role=HARD_NEGATIVE 的条目按此定义全部不达标（=0 严格 HN）**——本报告不再把它们当 HN 使用，在分析时以"用户直标 HN（3）"与"严格 HN（0）"双口径披露；
- 构造集的目标就是产出**严格定义**的 HN：人工核对时若 A/B 不符，按人工实际回答记录（可能又只有 3 个，也可能 10+），**不得诱导人工把 MEDIUM 改成 HIGH**。

## 八、Q7：重新审查 benchmark 成功标准

**建议把成功标准拆成两个独立门槛：**

### 7.1 测试集完整性门槛（冻结前置，非 Gate）
```
SP ≥ 20  且  SN ≥ 20  且  HN ≥ 10（严格定义）  且  历史回归集 3 案例在集
```
- **HN≥10 必须按严格定义统计**（当前 0 → 不冻结，这是当前阻塞的正当原因）；
- 若人工裁决后严格 HN 仍 <10：**不得降门槛、不得改标签**；改为输出 **INCONCLUSIVE（测试集不足）**，或由人工决定是否扩展构造集（继续单点补样本，非降门槛）；
- 此门槛是"能不能做实验"的判定，不是"系统好不好"的判定。

### 7.2 实验结果门槛（Gate 判定，不变）
```
B 达标（Top-5 usability≥60% ∧ rights=0 ∧ SP-retention≥80%）→ SUPPLY_IS_PRIMARY_BOTTLENECK
B 不达标 + C 达标 → SUPPLY_PLUS_VISUAL_UNDERSTANDING
B/C 均不达标 → 讨论 VISUAL_GENERATION_REQUIRED / DIRECTOR_LAYER_STILL_PRIMARY
证据不足 → INCONCLUSIVE
```

### 7.3 如何避免人为制造数据分布
1. **构造集独立记录**：`subset={natural, constructed}` 维度，`run_abc.py` 分别报告"自然集+合并"，主判定用**合并+自然集分列**双轨；
2. **构造规则预注册**（本文档 + hn_pool_design.json），先于系统输出确定，禁止事后为"通过"补样本；
3. **禁止**：改已有标签、降低 HN 门槛、把 CONITIONALLY_USABLE 改 NOT_USABLE、把 MEDIUM 改 HIGH、把"语义相关但主体错误"与"字面陷阱"混入普通负例统计；
4. **HN 回归集固定**：3 个历史案例 + 构造集组成"固定回归集"，任何未来实验必须保留且必须报告其下沉率（历史案例按人工实际标签，不按"期望的 HN"）。

## 九、Q8：最终建议

**采用 C = 定向构造 HN 专项集，作为唯一允许的补充路径。** 具体：

| 选项 | 裁决 | 理由 |
|---|---|---|
| A 继续机械抽样 | ❌ 不做 | 59 自然样本实测 HN=0，自然密度接近零且不可控，无法覆盖 9 类已知失败模式 |
| B 修改已有标签/降门槛 | ❌ **REJECT** | 数据操纵，制造假达标，直接污染实验。违反用户明令 |
| C 定向构造 HN 专项集 | ✅ **采用** | 构造独立于系统输出、标签仍人工冻结、可逐类覆盖已知失败模式；与 adversarial/hard-example 标准做法一致 |
| D 暂停素材供给实验，转其他能力层 | 暂不采用 | 当前阻塞是"测试集不完整"而非"方法不可行"；构造集成本低（一次定向检索+一轮人工标注），完成前不宜转场；但**如果构造集标注后严格 HN 仍 <10，则 D 自动成为备选**，并输出 INCONCLUSIVE（测试集不足） |

**执行清单（全部待人工授权，未授权前任何一个都不做）：**
1. 从 `hn_pool_design.json` 选 ≥12 个候选（覆盖 9 类）→ 生成 contact_sheet + labeling_manifest（HN 专项集 v1）；
2. 人工标注（A/B/C）；
3. 严格 HN 统计：≥10 且 SP/SN 保持 → 冻结 + 记录 SHA → 运行 A/B/C（需单独授权）；
4. 严格 HN <10 → STOP，输出 INCONCLUSIVE（测试集不足），由人工裁决转 D 或继续扩展；
5. 报告分列 natural/constructed 子集指标。

**最终立场：优先保护实验有效性。任何会造成标签污染或人为凑样本的方案（B、以及一切事后调整）一律 REJECT。**
