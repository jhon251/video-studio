## 2. 复核方法（一条权威链路 + 两种约定对照）

- **G10**：`orchestrator_core.g10_candidate_verdict`（生产原函数，逐字未改）+ **扩展信号库**（438 锚定池信号 + 262 新信号 = 701）——即"新检索轮次后生产会携带的状态"（G10 接线报告 §6：增量更新按新候选计）。
- **约定 P（生产口径）**：usability = **冻结 CV2**（老池 = `run03/cv2/cv2_results.json`，哈希 `d7cc5fbae37d52c3` 与 manifest 注册表一致；新候选 = 本次用**同一个冻结 `vision_call`**（model `deepseek-v4-flash-vision-exp` + 冻结 RUBRIC_PROMPT，focus 约定为空）判定的 252 条）。
- **约定 F（SS2 报告口径）**：usability = rubric-v2 池信号。
- **独立填充影子**：`build_content_index`（dHash≤6）内容身份 + 每内容全片 1 次 + 无借用 + 不足显式 `POOL_EXHAUSTED`；候选按 INTENT 顺序贪心。
- **不重跑检索**（pexels 检索仍用 SS2 已有 264 下载），唯一新增网络调用 = **252 次冻结 CV2 判定**（mean 8.05s / max 50.1s），因为"经过 CV2 后真正剩多少"这一验收问题在 SS2 中**根本没有用生产 CV2 回答过**。
