## 1. P18-1 `present_test` 口径修复（真 bug 已修）

**缺陷（P17 实证）**：旧版以「画面 vs 素材**全图**」比较，对**局部化/裁切/放大**呈现结构失效
（S08 rank 4/13、S13 rank 5/13 ⇒ 误判"非在屏"）。

**修复**：比较基准改为 **多尺度 16:9 子窗口 bank**
（`core/corr_diagnostics.py::bank_score`，尺度 {1.0,0.8,0.6,0.45,0.35} × 5×5 网格），
池内其它素材**同样按 bank 比较** ⇒ 「局部画面 vs 局部库」。`bank=False` 保留旧口径以便对照复现。

**回归实测**（`logs/phase18_p18_1_present_fix.json`）

| 景 | 旧口径 rank / corr / argmax | 修复口径 rank / corr / argmax |
|---|---|---|
| S02 | 1 / 0.1219 / ✔ | 1 / **0.6062** / ✔ |
| S06 | 1 / 0.2418 / ✔ | 1 / **0.5977** / ✔ |
| **S07** | **1** / 0.0783 / ✔ | **4** / 0.2766 / **✘** |
| **S08** | **4** / 0.0581 / ✘ | **1** / **0.7705** / ✔ |
| **S13** | **5** / 0.0062 / ✘ | **1** / **0.3763** / ✔ |
| **在屏数** | **3/5** | **4/5** |

**如实结论**：
- 修复**确实修掉了目标缺陷**（S08/S13 由 rank 4/5 变为 **rank 1**，证实"全图口径"是 bug）；
- 但**未达授权书要求的"五景全判在屏"（5/5）**：**S07 由 argmax 退化为 rank 4**——
  其 bank 最佳仅 0.2766，低于池内"最强误导素材"`301ff850be9c`（0.352）。原因是 bank 对
  **多面板素材**会让每个子窗口只覆盖部分内容，反而可能低于"全图 vs 全图"的表现。
- **该缺口未被掩盖**，且**未通过调参补救**；改由 P18-2/P18-3 处理（下方）。

## 3. P18-3 VLM 在屏核验层：**达标 ⇒ 已落地为仲裁层**

**任务边界（与 KNOWN_ISSUES #73 无关，写明）**：**视觉存在性**验证 ——
"帧中是否出现该素材的任何部分（允许裁切/缩放/局部）"，输出 `{present, absent, uncertain}` + 一句理由；
**不判**"配不配/合不合适"（那是 #73 的语义相关性问题，本层不涉及）。

**评测集（冻结）**：正例 = P17 五景帧包 × 3 帧（10%/50%/90%，人工目视真值"在屏"）= **15**；
负例 = 同帧 vs **池内 bank48 分数最高的 2 个其它素材**（确定性抽样）= **10**。
**达标线运行前写死**：与人工目视一致 **≥90%**；构造负例 **false-present = 0**；`uncertain` 按"不在屏"（fail-closed）。

**实测**（`logs/phase18_p18_3_vlm_presence.json`）

| 指标 | 实测 | 达标线 | 判定 |
|---|---|---|---|
| 与人工目视一致 | **25/25 = 100%** | ≥90% | ✔ |
| ├ 正例（在屏） | 15/15 | — | ✔ |
| └ 负例（错配） | 10/10 | — | ✔ |
| 构造负例 false-present | **0** | 0 | ✔ |
| uncertain | 0 | — | ✔ |
| 成本 | **$0.0180**（25 次调用） | ≤$0.5 | ✔ |

**关键能力证据（直击 P17 未解难题）**：
- **S07（corr 0.2766，确定性度量失败）** VLM 判 **present**：
  「成片帧完整包含素材原图的抛物线、三点连线、坐标标注及虚线结构，仅底部叠加了字幕」
- **S08** 判 present 并**准确指出被裁掉的部分**：「含相同点 A、B、C、E、Q、F 及虚实线连接关系，**仅缺失顶点 D 和底部 F 点**」
- **S13** 判 present：「可见与素材原图高度一致的类型推导图、Tactic state 结构及表达式 h = f ∘ g ∘ …」
  ⇒ **VLM 对"裁切/缩放/局部"的存在性判定稳健**，正是确定性度量失手的场景。

**仲裁层落地**（`logs/phase18_p18_3_arbitration.json`）

`corr < 0.30` ⇒ VLM 存在性核验：`present` ⇒ **放行**（附 VLM 证据 + prompt_version + 模型名）；
`absent` / `uncertain` / **调用失败** ⇒ **维持阻断**（fail-closed）。

| S06 | 0.5977 | PASS | NOT_NEEDED | **PASS_DETERMINISTIC** |

**未放宽真门**：阈值仍 0.30；仲裁**只在失败时**启用；`absent/uncertain/失败` 一律阻断；
**未改任何 PI 门禁逻辑**。
