## 1. P24-1 运动策略 v2（DONE：代码 + 度量）

### 1.1 代码升级（`core/motion.py`）
| 项 | v1 | **v2** |
|---|---|---|
| 运动窗口 | 景头 ≤`MOTION_WINDOW_MAX_FRAMES`(150) 帧，窗口外静止 | **摊满整景**（`motion = n_frames − 8`） |
| 启用比例上限 | `MAX_ENABLED_RATIO = 0.6` | **`MAX_ENABLED_RATIO_V2 = 1.0`**（全镜） |
| hook 强制 | 仅靠排序优先 | **`force_hook`**（cap 之外也强制启用 S01） |
| 步长模型 | 整数 2px/单位步（`ZOOM_STEP_PX`） | **直接 Q8 进度** `w(n)=w_end+(motion−c)·Δ/motion` |
| 幅度上限 | `MAX_ZOOM_END = 1.08` | **不变**（1.08） |
| `<10s` prefer-STATIC | 保留 | **保留** |

**全片计划**：21 景 / **启用 21 景** / 总时长 978.7s；逐景 `zoom_end = 1.0799`（≤1.08）、
`motion_frames ≈ 整景帧数`。**闭式（`evaluate_closed_form`/`crop_filter`）与逐帧 `rects`
逐帧一致（0 处不一致）**，且唯一宽度值 **143**（真正连续推进，而非几步跳变）。

**过程中修掉三个真 bug（如实登记）**
1. **推进走不满幅度**：v1 的 `_stage_frames` 是为 ≤150 帧窗口设计的 50/75/25 分配；
   沿用到整景只用到 148+446+148 帧 ⇒ 推进在景末前停止（终点宽度 1885 ≠ w_end 1778）。
   改为**三阶段铺满整景**并收敛到恰好 `motion` 帧。
2. **单位量化不可行**：8% 幅度 = 142px = **71 个单位**（2px/单位）；摊到 750 帧时
   **整数单位步长只能是 0 或 1** ⇒ 要么头 142 帧走完、其余静止，要么走不满。
   改为**绕过"单位"量化、直接在像素精度上按帧插值**（Q8 定点），才既满足 ≤1.08 又摊满整景。
   同时**完全绕开 `_steps`**：其整数最小步长在短景上无解（如 2.6s 景只有 57 帧，
   走完 71 个单位需 ≥142 帧），旧实现会因此回退静止**并改写 `motion`**，破坏"摊满整景"。
3. **平移分支未同步升级**：`build_plan` 对**偶数 scene_id** 用 `SLOW_PAN`；
   首版只改了 zoom 分支 ⇒ 偶数景仍是 v1 口径（`motion = min(avail, total, 150)`，
   实测被截成 57/150 帧）。已把**平移也改为全镜均匀插值**（`off = c·pan_px/motion`），
   `evaluate_closed_form` / `crop_filter` 同步 ⇒ 两分支均摊满整景且闭式逐帧一致。

### 1.2 验收度量（新增 `core/motion_metrics.py`，逐秒差分法）
方法：1 fps 抽帧 → 160×90 灰度 → 相邻抽帧 MAD；`MAD < 0.05` ⇒ 该秒判冻结。
三指标运行前写死：冻结占比 **<50%**、最长连续静止 **<25s**、开场 90s 内变化 **≥3 次**。

**⚠️ 为什么不用 `freezedetect`（重要发现）**：实测在 H.264 CRF20 下，
`freezedetect` 对**真实冻结画面也报 0%**（见 `logs/phase24_p24_1_probe.json`：6 组配置全部 0.00s）——
编码噪声抖动会持续超过噪声阈值 ⇒ 它是「噪声阈值」度量，不是「内容运动」度量。
监理的 94.8% 基线**并非由该方法得出**（方法未同源）。逐秒差分法直接量测**内容变化**，
更贴合"观众看到的画面是否在动"，故采用授权书原本指定的口径。

**实测（20s 探针短片）**：冻结占比 **73.7%** ✘｜最长静止 **9.0s** ✔｜开场变化 **5 次** ✔
（MAD 中位数 **0.0** ⇒ 绝大多数相邻秒**逐像素完全相同**）

### 1.3 ⚠️ 核心结论：三指标与授权幅度上限**数学不相容**
| 时长 | zoom_end | 总推进 | 探针尺度 px/秒 | 要达 1px/s 所需总 zoom |
|---|---|---|---|---|
| 20s | 1.0799 | 142px | **0.59** | **112%** |
| 30s | 1.0799 | 142px | 0.39 | 119% |
| 44.5s | 1.0799 | 142px | 0.27 | 128% |
| 67.4s | 1.0799 | 142px | 0.18 | 142% |
| 88s | 1.0799 | 142px | 0.13 | 155% |

**推导**：`zoom ≤1.08` ⇒ 1920px 画布总推进 **142px**；探针宽 160px ⇒ 每 1px 探针变化需
全分辨率 **12px** 推进；整景只有 142px ⇒ 探针上总变化 **≈11.8px**。
摊满 20s ⇒ **0.59 px/秒**，**远低于 1px/s 的可感知阈值**。
要在 20s 内每秒产生 ≥1px（探针）变化，需每秒放大约 0.62% ⇒ 20s 累计约 **112%**，远超 1.08。

⇒ **授权同时要求「zoom ≤1.08 / pan ≤3%」与「冻结占比 <50%、最长静止 <25s」，
在低细节静态图片素材上不可兼得。** 冻结占比由「每秒可见内容变化」决定，
而该变化的**上界被幅度上限锁定**。这不是实现问题，而是**约束冲突**。

**⟹ 请裁定（四选一或组合）**
| 选项 | 内容 | 代价 |
|---|---|---|
| **① 放宽幅度上限** | 如 zoom ≤1.25，或允许**整幅平移**动画（平移不受 zoom 上限约束，可给足位移） | 需确认不威胁逐景 `corr ≥0.30` 核验（平移会改变画面构图） |
| **② 换素材策略** | 改用**本身含运动**的素材（视频片段），或**多图快切** | 需补池（受治理获取）与素材许可复核 |
| **③ 图内元素动画** | 图注/箭头/高亮**逐段揭示**，而非整体缓推 | 工程量最大；但最贴合"知识型解说"画面语言 |
| **④ 重定义该指标** | 如按 **5s 窗口**而非 1s 窗口计冻结 | 指标口径变更需授权；且**不改变观众实际观感** |

> 依授权书「三指标运行前写死」+「完成即 STOP」：**我未自行放宽任何阈值、未改口径**。
