| 度量 | 正门 | 反门 |

**结论（如实）**：**正门未达 100%**。两处关键事实：
1. **v2 修好了 P31 的目标景**：S11p2 **0.2703 → 0.3199**、S13p2 **0.2846 → 0.3332**（均过 0.30）。
2. **v2 在稀疏线稿上回落**：S06 0.674 → 0.385、S07 0.449 → 0.279、S13 0.509 → 0.337；
   原因是**分辨率提升反而不利于稀疏线稿**（P17 已登记的 `density_artifact` 反向表现）。
   ⇒ 取 `max(v1,v2)` 可消除回落但仍为 15/17（唯一残项 **S07 frame_50 = 0.2766**）。
3. **重要限定**：该历史语料上**冻结的 v1 自身也只有 13/17** ⇒
   "正门 100%"这一判据**不是 v2 引入的回归**，而是该语料/阈值本身的边界
   （S07 frame_50 在 v1/v2/SSIM 三种口径下均 < 0.30）。

### 2.3 反门与"是否为放宽"的说明
反门语料须先**去污染**：P17 attr_pack 里 S06 的声明素材就是 `301ff850be9c`，
把"S02/S07 画面 × `301ff850be9c`"当负例是正确的（画面属别的景），
但把"某景画面 × 其**同类复用**素材"当负例则是错的。去污染后反门仍有误通过项
（含 S08 × `5144139591a0` 等），**v1 与 v2 都存在**。
⇒ **本阶段未以"反门通过"作为采纳理由**，也**未改动阈值或口径**；
采纳理由来自 §2.4 的**生产实测**，并已如实登记正门未达 100%。

### 2.4 决定性证据：生产 40 景实测 + 一处**静默降级**缺陷的修复
**发现的缺陷**：把 `bank_derived` 迁到外部链后，首轮生产渲染的核验证据里
`bank_derived=True / bank_version=bank-derived-v2`，但 **`corr_bank` 全为 None、
无景带 bank 窗口** ⇒ 走的是**全图 corr 回退**（即名义 v2、实际 v1 全图）。
**根因**：生产链统一用 `gray48`（48×48）取帧，而 v2 需要 192×192 ⇒
`_corr` 形状不匹配抛 `ValueError`，被**裸 `except` 静默吞掉**并回落到全图口径
（**P28 §0 明令禁止的"静默回落"**）。
**修复**：
1. `bank_score_of` 增加 `_as_res()`：**探针帧自动规整到该版本分辨率**（v1 已是 48 ⇒ 逐字节不变）；
2. `_verify_scene_frames` 在 v2 下**以 192 分辨率重新载入画面**（而不是把 48 上采样，
   后者不增加真实细节）；
3. 该分支的 `except` 改为**记录 `bank_error`**（不再静默）。

**修复后生产实测（沙箱 `p_e0cda0a7d541`）**：

| 指标 | 修复前（名义 v2） | **修复后（真 v2）** |
|---|---|---|
| 含 `corr_bank` 的景 | **0 / 40** | **32 / 40**（其余 8 为纯色卡景，本就不参与） |
| `bank_error` | —（被吞） | **0** |
| 逐景核验 `failed` | 0（但结论来自全图口径） | **0** |
| 需 VLM 仲裁的景 | 12 | **2** |
| **S11p2** | 0.0914（全图） | **0.3199 ✔（过阈）** |
| **S13p2** | 0.0834（全图） | **0.3332 ✔（过阈）** |
| 其余上升样例 | — | S06p2 0.139→**0.9236**、S08p2 0.062→**0.9561**、S13p1 0.135→（纯色卡）、S18p1 0.274→**0.6485** |

⇒ **采纳 `bank-derived-v2`**：它是**生产上唯一能把派生段核验拉回 ≥0.30 的口径**，
