## 1. P25-1 运动 v2.1：DONE

### 1.1 幅度上修（POLICY）
| 常量 | P24 | **P25** | 说明 |
|---|---|---|---|
| `MAX_ZOOM_END` | 1.08 | **1.25** | 授权上修；`plan_scene` 的 `zoom_end` 不再硬编码 1.08 |
| `MAX_ZOOM_END_V1` | — | **1.08** | **守卫降级目标**（新增，保留旧上限语义） |
| `CORR_GUARD_MIN` | — | **0.30** | 每景 corr 守卫阈值（与冻结口径一致） |
| `PAN_MAX_RATIO` | 0.03 | 0.03 | 不变（整幅平移按现口径允许） |
| 全镜插值框架 | P24-1 | **沿用** | 像素级 Q8 逐帧插值，闭式与 rects 逐帧一致 |

**新增 `zoom_max` 参数**（`plan_scene`）：缺省用 1.25；显式传 1.08 ⇒ 该景幅度回到旧上限
（守卫重渲路径）。**总推进：1.25 ⇒ 384px；1.08 ⇒ 142px**（1920 基准）。

**⚠️ 与授权书推导的差异（如实登记）**：授权书写「1.25 幅度 ⇒ 480px 推进」。
本实现的 `w_end = out_w / zoom_end = 1920 / 1.25 = 1536` ⇒ 总推进 **384px**（不是 480）。
480 对应的是 `w_end = 1440`（即 1.333 倍）。两种口径的**倍数关系一致（×1.25）**，
仅"幅度"的基准不同（授权按 `out_w×1.25`，实现按 `out_w/1.25` 的逆向语义）。
**384px 已足够**：实测三指标全过（见 §1.3），故**未改语义**。

### 1.2 每景 corr 守卫（硬性，新增 `core/motion_guard.py`）
```
渲染后逐景复核 corr → corr < 0.30 ⇒ 该景幅度降回 MAX_ZOOM_END_V1(1.08) 重渲
                     → 登记 MOTION_DOWNGRADED（附 from/to 幅度与实测 corr）
                     → 仲裁层（core/render_arbitration.py）照旧兜底
```
- `guarded_scenes(plan, scene_corrs)` → `{downgrade, keep, unknown, records, all_pass}`
- `rebuild_plan_with_guard(...)` → 降级景用 `zoom_max=1.08` **重算**，未降级景**不受影响**；
  `plan.counts.downgraded` 与守卫一致；内嵌 `plan.guard` 摘要
- **确定性**：同输入同输出；**只调运动参数**，不改 corr 判定阈值、不改仲裁语义（授权边界）
- **边界处理**：恰等于 0.30 ⇒ **不降级**；corr **缺失** ⇒ `KEEP_UNKNOWN`（登记但不降级，待复核）

**40 景实测演习**（合成 corr，验证守卫在真实 40 段 id 上工作）：
启用 **40/40** 景、**降级 13** 景（`S02p2/S04p1/S05p2/S07p1/S08p2/S10p1/S11p2/S13p1/S14p2/S16p1/S17p2/S19p1/S21p1`）、
降级景幅度均 ≤1.08 ✔、`counts.downgraded=13` ✔。

**顺带修掉一个 P25 才暴露的 bug**：`build_plan` 用 `int(str(scene_id).lstrip("S"))` 解析
父景序号，对**派生段 id**（`S02p1`）抛 `ValueError` ⇒ 新增 `_scene_ordinal()`（正则取前导数字，
异常返回 0）。40 景含派生段 id，**P24 的单段测试覆盖不到**。

### 1.3 三指标：**实测全过**（`logs/phase25_p25_1_motion_v21.json`）
探针 **320×180**（授权推导隐含该宽度）、1 fps、`MAD < 0.05` 判冻结；阈值**运行前写死**。

| 指标 | 阈值 | **P24（1.08 幅度）** | **P25（1.25 幅度）** | 判定 |
|---|---|---|---|---|
| 冻结占比 | <50% | **73.7%** ✘ | **0.0%** | ✔ |
| 最长连续静止 | <25s | 9.0s | **0.0s** | ✔ |
| 开场 90s 变化 | ≥3 次 | 5 | **23** | ✔ |
| MAD 中位数 | — | **0.0** | **10.23** | — |

**分辨率并列实测（同一 1.25 短片）**：`160×90 → 冻结 0.0% / MAD 8.81`、
`320×180 → 0.0% / 10.23`、`480×270 → 0.0% / 10.86` ⇒ **1.25 幅度下三种探针都过**。
> **更正 P24 的归因（如实登记）**：P24 曾把失败归因于"探针分辨率 + 幅度上限的双重约束"。
> P25 实测表明**主因是幅度**（1.08 的 142px 太小），分辨率只是敏感度系数；
> 1.25 的 384px 在任何常用探针下都过。P24 的"分辨率决定成败"表述**过强，此处更正**。
