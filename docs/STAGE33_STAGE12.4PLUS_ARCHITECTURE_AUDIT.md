# Stage 12.4+ 架构审计：为什么成片仍是"随机素材拼接"

> 性质:仅代码审计与架构分析。未修改任何既有文件。CV-2/V1/Gold 等冻结组件未动。
> 所有判断基于真实代码与真实测试产物(stage10/11/12.x 的 json 与 MP4)。

---

## 0. 决定性数据(本轮实测)

1. **Stage 12.1 kept 池类型分布:24/24 = 100% DOC,0 张真实照片**(gate 前新池 78 DOC / 0 IMG);
2. **Commons 加图片类型约束后**,同一批视觉意图能返回真实照片:smart city aerial → 城市航拍/无人机;robot human collaboration → 协作机器人/ISS;
3. **S04 honest-empty 可被修复**:同一意图在图片约束下有真实候选(此前 kept=0 是检索层问题,不是"Commons 没素材");
4. **AI 历史段的 Dartmouth 提案 PDF 恰是正确档案素材**——证明"文档不该一刀切禁止,该按叙事意图准入"。

---

## A. 为什么仍然"随机素材拼接"?

四层原因,按因果顺序:

1. **检索层返回的是文档扫描件,不是照片(最根本)**。
   Commons `gsrsearch`(namespace 6 全文搜索)匹配文件**描述文本**;archive.org 批量上传的文档扫描在索引里占绝对主导。Stage 12.1 的 intent-aware query 精炼成 2-6 个英文名词短语后,全文检索命中的几乎全是文档(78 DOC / 0 IMG)。**V1 和 CV-2 只能在池内排序——池里没有照片,它们不可能选出照片。** 下游全部正确,上游无米下锅。

2. **1 shot = 1 张静态图 × 全旁白时长(~17s)**。
   没有视觉节拍(beat)概念。无论图多合适,17 秒静止一张图,天然是 PPT。

3. **无跨镜头视觉叙事**。
   每镜独立选图;章节级视觉语言(历史段=档案/当前段=产品/社会段=人/未来段=概念)只存在于 12.3 的 policy 里,但池里 100% DOC,无素材可差异化。

4. **Visual Intent 没有贯穿到最终选择**。
   Intent 只用于 query + gate;V1/CV-2 最终排序时看不到 intent。Gate 判过相关后,intent 就"断线"了。

**结论**:不是 CV-2 错,不是 V1 错,不是 gate 错——是**系统从来没有给它们喂过照片**。

## B. 链上最大剩余瓶颈

**Retrieval 层的池构成(pool composition)**,具体两点:
- 无图片类型约束:`gsrsearch` 全文搜索天然偏向文档扫描;
- query 精炼丢信息:LLM 压缩成短英文短语后,全文检索按描述文本匹配文档而非图像文件。

Gate 工作正常(语义拦截正确),但它的**成功标准过窄**:12.1 验收是"kept 候选主题相关"——24 个语义相关的文档全部通过,掩盖了"视频需要的是视觉素材"这一根本需求。**这是我此前 Stage 12.1 验收设计的缺陷:把'主题相关'当成了'可用',没有把'媒体类型适配视频'纳入验收。**

## C. 旁白↔画面的真正一一对应

三步:
1. **Intent 成为选择链的常驻约束**:gate 已做语义判断;再加一层"最终选中素材的 visual_subject/visual_action 与 intent 的语义复核"(复用现有 gate LLM,零新模型);
2. **节拍化**:把一镜旁白拆成 2-4 个视觉节拍,每节拍 5-8s、各自选图——旁白讲三件事,画面就有三个画面;
3. **验收以"画面可回答"为准**:CONTENT_ANCHOR_TEST 扩展为"只看画面(无字幕)能否说出镜头主题"——字幕可以辅助,但不能是唯一信息载体(当前正是字幕扛起全部语义)。

## D. 避免长时间展示论文/PDF 截图

三个机制(无类型黑名单):
1. **检索准入**:视觉意图(asset_type_hint=IMAGE)默认图片优先检索(`filetype:bitmap`);仅当 time_period=historical 或 asset_type_hint=DOCUMENT(如 AI 历史 Dartmouth 提案)才检索档案——**按叙事意图准入,不是按类型拒绝**;
2. **呈现约束**:文档入选时(Stage 12.3 已有 DETAIL_CROP/FRAMED)叠加"单图停留 ≤8-10s"(节拍化天然实现)+ Ken Burns scan;
3. **节奏规则**:连续 DOCUMENT 镜头禁入(12.3 已有 policy;修复检索后池里有照片,policy 才有的选)。

## E. 建立真正的视觉叙事(而非逐镜独立选图)

新增**Storyboard(分镜脚本)层**:Narrative sections → 视觉调色板 → 每节拍的 asset_type 计划,然后逐节拍走 intent→query→gate→CV-2。跨镜头约束:相邻镜 asset_type 交替(person/scene/data)、章节内视觉语言一致、复用受控。这样 12.2 motion 与 12.3 composition 才真正"有的可编排"。

## F. 8-12 分钟会放大什么

1. 36 镜 × 17s × 1 文档图 = **全片都是论文封面**;
2. role 循环 4-5 遍 → 相似 query 重复 → 相同/近似文档反复出现(重复感倍增);
3. 字幕成为唯一语义载体(用户实测"无字幕无法理解")——画面语义缺席被拉满;
4. 旁白提及具体场景(办公室/城市/教育)与画面(无关论文封面)的错位持续累积;
5. F5 CPU 渲染 ~3h(工程问题,但**质量问题优先**:内容不值得渲染就不该渲染)。

## G. 最值得修改的 1-3 处(最小方案)

**修改 1:Retrieval v1.5——图片优先检索(最高杠杆,改动最小)**
- `query_generator` 增加 `filetype` 字段:asset_type_hint=IMAGE → `filetype:bitmap`;DOCUMENT/historical → 不加(允许档案);
- 检索侧透传该约束;池内无图 → honest empty(如 modern office 自动化场景,如实报告);
- 预期:池从 78 DOC/0 IMG → 多数镜有真实照片;S04 honest-empty 修复;CV-2 首次有真实照片可排;文档仅在历史段合法出现。
- 改动量:~30 行,不碰冻结组件。

**修改 2:Visual Beat Segmentation(结构性消灭 PPT 感)**
- 新模块:每镜旁白按语义切成 2-4 个节拍(复用 hardened LLM + split 句法),每节拍独立 intent→query→gate→CV-2 选图,5-8s/图;
- 预期:画面密度×2-3,单图停留时间减半,信息节奏感形成。

**修改 3:Storyboard 层(章节视觉叙事)**
- sections → 视觉调色板(历史=archive/当前=tech/社会=human/未来=conceptual)→ 节拍级 asset_type 计划;跨镜头交替约束;
- 预期:消除"连续论文截图",形成"历史→当前→社会→未来"的视觉语言演进。

**建议顺序**:先 1(一个小改动即可让下游全部受益并复测),再 2,再 3。每个独立可验收。

## 对 Stage 12.x 设计缺陷的直接指出(不迁就历史结论)

- **12.1 验收标准过窄**:只验"主题相关",未验"媒体类型适配视频"——导致 gate PASS 但池仍是全文档;`modern office` 类意图真实缺素材应更早暴露;
- **12.2 真实 6-shot 全 STATIC 正确但无信息量**,运动多样性只靠合成用例证明——真实演示被上游池问题阻断;
- **12.3 policy 正确但无米之炊**——池 100% DOC 时 composition 只是"换着花样展示文档";
- **12.4 的 50.8s PASS 是工程闭环 PASS**——画面本身仍是 3 张文档页,字幕扛起全部语义;这与"LONG_FORM_VIDEO_QUALITY=NOT_READY"一致,但当时未把"池构成"列为第一阻塞项。
